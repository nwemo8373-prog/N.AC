# NEGM APP BUILDER — حزمة بداية قابلة للتشغيل

هذه الحزمة تتضمن واجهة ويب عربية RTL، وخدمة بناء خلفية تستعمل Android SDK وGradle لإنشاء APK من مشروع HTML مضغوط.

## محتويات ZIP

- `index.html`: واجهة إعداد المشروع، التصميم، الصلاحيات، إعدادات الإشعارات، حفظ المسودة محليًا، وتكامل اختياري مع Firebase Realtime Database.
- `backend/server.js`: خدمة Node.js تستقبل ملف ZIP وإعدادات المشروع، تولّد مشروع Android مؤقتًا، وتشغّل Gradle.
- `backend/Dockerfile`: صورة بناء تشمل JDK وGradle وAndroid SDK Platform 35.
- `firebase-database-rules.example.json`: مثال لقواعد Realtime Database. عدّلها لتتوافق مع تسجيل الدخول الفعلي قبل الاستخدام.

## مهم قبل التشغيل

1. `https://hedars-ai.firebaseapp.com` هو نطاق Firebase Hosting/Auth، وليس بالضرورة عنوان Realtime Database. افتح Firebase Console ثم Realtime Database وانسخ `Database URL` الصحيح وضعه في الواجهة.
2. الواجهة لا ترفع الصور إلى Firebase Storage. صور HTML وCSS وJS داخل ZIP تُنسخ إلى `app/src/main/assets/www` داخل APK.
3. بناء APK يحتاج خادمًا يشغّل Android SDK وGradle. لا يمكن بناء APK فعلي من HTML وحده أو من Firebase Realtime Database وحدها.
4. اضبط `BUILD_TOKEN` و`ALLOWED_ORIGIN` قبل نشر خدمة البناء على الإنترنت. لا تترك الخدمة عامة دون حماية. استخدم HTTPS، حدودًا للاستهلاك، وبيئة معزولة للبناء.
5. خدمة البناء الحالية هي إصدار بداية وظيفي وليس ضمانًا أن أي مشروع HTML سيعمل دون تعديل. المشاريع التي تعتمد على واجهات API أو أذونات WebView متقدمة قد تحتاج تخصيصًا واختبارات على أجهزة حقيقية.
6. الإشعارات المحلية المجدولة مدعومة بصورة أولية. إشعارات FCM الفورية تحتاج إعداد Firebase Cloud Messaging وخادم إرسال آمن؛ مفاتيح الخادم لا توضع في HTML أو APK. الإشعار اليومي/الأسبوعي قد يتأثر بسياسات توفير الطاقة في بعض الأجهزة، ويجب اختباره.
7. اختيار أيقونة التطبيق في واجهة الويب محفوظ كبيانات إعداد، لكن إعداد أيقونة launcher تلقائيًا يحتاج استكمال معالجة موارد Android قبل اعتبار الحزمة مناسبة للنشر العام.
8. لا تضع كلمات مرور أو مفاتيح خاصة في الواجهة. قواعد Firebase العامة للقراءة والكتابة غير آمنة.

## تشغيل خدمة البناء باستخدام Docker

من مجلد `backend`:

```bash
docker build -t negm-app-builder .
docker run --rm -p 8787:8787 \
  -e BUILD_TOKEN='ضع-رمز-طويل-وعشوائي-هنا' \
  -e ALLOWED_ORIGIN='https://your-site.example' \
  negm-app-builder
```

ثم ضع رابط الخدمة في خانة «رابط خادم البناء» بالواجهة. في هذا المثال، استخدم عنوان HTTPS أمام الخدمة عند نشرها؛ لا تضع خدمة البناء مباشرة على الإنترنت دون طبقة TLS وحماية.

## تشغيل محلي دون Docker

يتطلب Node.js 20+، وGradle 8.10+، وJDK 17، وAndroid SDK مع `platforms;android-35` و`build-tools;35.0.0`:

```bash
cd backend
npm install
export BUILD_TOKEN='ضع-رمز-طويل-وعشوائي-هنا'
export ALLOWED_ORIGIN='http://localhost:8080'
npm start
```

افتح `index.html` من خادم ويب محلي أو استضافة HTTPS، ثم اكتب عنوان خدمة البناء.

## تنسيق ZIP المطلوب

يجب أن يحتوي ZIP على `index.html` في الجذر، وبجواره ملفات CSS وJavaScript والصور التي يستخدمها الموقع. مثال:

```text
my-site.zip
├── index.html
├── css/
│   └── style.css
├── js/
│   └── app.js
└── images/
    └── logo.png
```

## Firebase

تستخدم الواجهة REST API لـ Realtime Database لحفظ إعدادات المشروع فقط، عند إدخال Database URL صحيح. يجب أن يكون المستخدم مصادقًا عليه إذا كانت قواعدك تتطلب ذلك؛ النسخة الحالية لا تنفّذ تسجيل دخول Firebase داخل الواجهة. لا تجعل القواعد عامة لتجاوز هذه الخطوة.

## حدود السلامة والجودة

- الخدمة تحدد حجم الرفع بـ 50MB افتراضيًا وتحد عدد الملفات بعد فك الضغط.
- استخدم عزلًا على مستوى نظام التشغيل/الحاويات وحدود CPU/RAM ووقت تنفيذ عند تشغيل الخدمة العامة.
- راجع الملفات المرفوعة ولا تشغّل سكربتات المشروع المرفوع أثناء البناء.
- الناتج الافتراضي APK تجريبي موقّع بمفتاح debug، مناسب للاختبار فقط، وليس لتوزيع إصدار إنتاجي أو نشره في المتجر. يتطلب إصدار الإنتاج توقيعًا بمفتاحك الخاص وإدارة آمنة له.
